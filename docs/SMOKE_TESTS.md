# Post-deployment smoke tests

`scripts/smoke/production-smoke.mjs` runs read-only checks against one deployed API. It is for a deployment that has
been named explicitly. It is never run during development, and nothing in this repository points it at a real service.

## Refusals

The script refuses to run, and exits with status 2, unless all of these are true:

- `SMOKE_BASE_URL` is an https origin with no path, query, or credentials.
- `SMOKE_TARGET` is `disposable-staging` or `production-verification`.
- `SMOKE_ALLOWED_HOST` exactly equals the hostname in `SMOKE_BASE_URL`. This is a deliberate second confirmation.

Destructive checks run only when `SMOKE_ALLOW_DESTRUCTIVE=true` **and** `SMOKE_DISPOSABLE_UID` names a disposable
synthetic account. Account deletion is not part of the script. It is verified by the emulator suite and by a manual
step against a disposable account (below).

## Usage

```bash
# Print the plan without any network call
SMOKE_BASE_URL=https://api.example.test SMOKE_TARGET=disposable-staging \
  SMOKE_ALLOWED_HOST=api.example.test node scripts/smoke/production-smoke.mjs --dry-run

# Read-only checks (add SMOKE_STUDENT_TOKEN for the authenticated checks)
SMOKE_BASE_URL=https://api.example.test SMOKE_TARGET=disposable-staging \
  SMOKE_ALLOWED_HOST=api.example.test SMOKE_STUDENT_TOKEN="$TOKEN" \
  SMOKE_ORIGIN=https://app.example.test node scripts/smoke/production-smoke.mjs
```

Pass the student token through the environment only. The script never prints a token, and its output contains only
check names, pass or fail, and status codes.

## What the read-only checks cover

| Check | Expectation |
| --- | --- |
| Liveness, readiness | `200` each |
| Mode | `production` with auth configured |
| Anonymous profile access | `401` |
| Forged `x-demo-user` | `401` |
| Foreign origin | No `Access-Control-Allow-Origin` |
| Configured client origin | Allowed |
| Security headers | `nosniff` and a Content-Security-Policy |
| Updates feed | `200` with a `sourceHealth` summary (signed in) |
| Authenticated profile, tasks, documents, resources, export | `200` (signed in) |
| Student on admin review | `403` |
| Scheduler without its secret | `401` or `503` |

## Checks that need a person

These are not automated because they need live services or a human judgement. Record the outcome on the release.

- Real Google sign-in and its consent screen, using a synthetic Google account.
- Document upload to the live Storage bucket with the synthetic PDF, PNG, and JPEG fixtures in
  `server/tests/fixtures/documents/`, including the scanned PDF ("no readable text", upload kept).
- A grounded answer, an insufficient-evidence answer, and an attorney referral against the synthetic documents.
- Cross-account isolation between two synthetic accounts: the second account cannot read the first account's
  documents, conversations, or export.
- Account deletion from a fresh sign-in, against a disposable synthetic account with one task and one document.
  Confirm the old token returns `401`, the Firestore tree is gone, the Storage prefix is empty, and the Auth user is gone.
- Source synchronization: one dry run, then one live run of the approved source, then `GET /api/news` shows
  `sourceHealth.state` moving from `not-checked` to `current`.
- Logs and alerts: the structured lines arrive in the chosen collector, and `audit.*` events are visible.

## Fixtures

Every fixture is synthetic and generated by `server/tests/fixtures/documents/generate.py`. None is a real identity
document.
